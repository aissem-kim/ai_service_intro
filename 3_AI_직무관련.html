직무별 학습 로드맵

아래 탭을 눌러 5개 직무의 단계별 경로를 비교하세요.

ROADMAP // 4-1

AI 앱 개발자 가장 추천

기존 웹/백엔드 역량이 그대로 쓰이는 경로입니다. 공고 요구사항의 상당 부분이 이미 배운 것과 겹칩니다.

단계별 로드맵
단계학습 내용산출물
0Python, HTTP/REST, Git간단한 CRUD API
1LLM API (호출·스트리밍·비용·에러처리)텍스트 요약 CLI 도구
2구조화 출력(JSON 스키마), Tool calling (툴 콜링)문의 자동 분류 API
3백엔드 통합 (FastAPI + DB + 인증)사용자 계정 있는 AI 웹앱
4배포 (Docker, 클라우드)실제 접속 가능한 URL
ROADMAP // 4-2

AI 엔지니어 (RAG / 에이전트)

검색 품질을 수치로 개선할 수 있는 사람을 뽑습니다. "만들었다"가 아니라 "재고 올렸다"를 말할 수 있어야 합니다.

단계별 로드맵
단계학습 내용산출물
0(AI 앱 개발자 0~2단계 선행)—
1임베딩, 벡터 검색 원리문서 유사도 검색기
2청킹 전략, 하이브리드 검색, 리랭킹RAG 챗봇 v1
3검색 품질 측정 (Recall@k, MRR)청킹 전략별 성능 비교 리포트
4에이전트 — 툴 콜링, 상태 관리, 재시도다단계 업무 에이전트
차별화 포인트 — 대부분의 지원자가 "RAG 챗봇 만들었습니다"에서 멈춥니다. "청킹 사이즈를 512에서 256으로 줄여 Recall@5가 0.71 → 0.84로 올랐습니다"라고 말할 수 있으면 그 자체가 합격 요인입니다.
ROADMAP // 4-3

AI 품질/평가 (Eval)

코딩 부담이 상대적으로 적은 틈새 영역. 관측(89%)과 평가(52.4%) 사이의 약 37%p 실무 격차가 이 직무가 필요해지는 이유입니다.

단계별 로드맵
단계학습 내용산출물
1평가셋 설계 — 무엇을 측정할 것인가평가 기준 문서(rubric)
2규칙 기반 자동 평가 (정확도, 형식, 금칙어)자동 채점 스크립트
3LLM-as-a-Judge, 사람 평가와의 일치도판정 신뢰도 검증 리포트
4회귀 테스트, 관측 도구 (Langfuse 등)대시보드
3계층 평가 구조 (실무 표준)

1층 · PR마다 빠른 검사

형식·툴콜링 유효성처럼 규칙으로 즉시 판정 가능한 항목.

2층 · 야간 회귀 테스트

LLM 판정으로 품질 회귀를 탐지합니다.

3층 · 운영 중 상시 모니터링

실사용 트래픽에서 성능 드리프트를 감지합니다.

ROADMAP // 4-4

LLMOps

배포·관측·비용을 책임지는 자리. Linux·Docker·Git이 선행 조건이라 진입은 높지만, 지원자가 적습니다.

단계별 로드맵
단계학습 내용산출물
0(Linux, Docker, Git 선행 필수)—
1배포 파이프라인, 환경 분리CI/CD로 자동 배포되는 AI API
2관측 — 트레이싱, 로깅, OpenTelemetry요청 단위 추적 대시보드
3비용 최적화 — 캐싱, 모델 라우팅, 토큰 절감비용 40% 절감 실험 리포트
4안정성 — 레이트리밋, 폴백, 서킷브레이커장애 시나리오 대응 문서
포트폴리오 관점 — 3단계의 "비용 X% 절감 리포트"는 면접에서 숫자로 말할 수 있는 몇 안 되는 산출물입니다. 우선순위를 여기에 두세요.
ROADMAP // 4-5

AI 서비스 기획 / PM

코드를 쓰지 않지만 AI의 한계를 가장 정확히 알아야 하는 자리. 도메인 경험이 곧 무기가 됩니다.

단계별 로드맵
단계학습 내용산출물
1AI가 잘하는 것 / 못하는 것 구분적용 후보 업무 10개 평가표
2요구사항 정의 — 성공 기준을 숫자로PRD 1건
3노코드/저코드 프로토타이핑동작하는 프로토타입
4비용·리스크 산정ROI 추정 시트
핵심 역량 — "이 업무에 AI를 쓰면 안 되는 이유"를 말할 수 있는 기획자가 신뢰받습니다.
